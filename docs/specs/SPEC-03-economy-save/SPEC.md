# SPEC-03｜商店經濟、背包與防損存檔

## 1. 這個 SPEC 的目的是什麼？

打通拾暖的**商業驗證閉環**與**玩家進度安全底線**：
1. **讓「原生廣告商店」真正做到無反感又好玩：** 玩家靠日常陪伴與「閱讀真實貓食營養成分滿 3 秒」自然累積積分、選購罐頭與零食放進背包；同時堅持免費乾糧與飲水無限供應，絕不用扣血逼課金。
2. **讓玩家養了幾個月的貓永遠不會壞檔或變臉：** 透過「先寫暫存 → 讀回驗證 → 備份舊檔 → 原子替換」四步防損機制與 `v1 → v2` 版本遷移，就算手機突然沒電或版本升級，貓咪的長相、個性與低心情累計進度也 100% 完整保留。

---

## 2. 要完成哪些功能？

### In-Scope（本 SPEC 涵蓋）
- **積分與雙重防重每日獎勵（`EconomyEngine`）：**
  - 開局 200 積分（永不為負）。
  - 每日簽到 `+40` 積分（本地日期 ＋ 20 小時冷卻雙重防重，防止調錶刷分）。
  - 商店首開 `+5` 積分；檢視上架商品成分頁停留 `>= 3 秒` 每款不重複 `+10` 積分（日上限 30，同日重複開不重複給分）。
  - 撫摸／玩耍每次 `+5` 積分（日上限 25），**超過上限後 `mood +3` 照常生效**，不阻斷陪伴與救援。
  - 跨日高健康日結獎勵 `+25` 積分（`health >= 90 && mood >= 80`，不補發漏日）。
- **公平商品購買與背包消耗：** 免費基礎糧水無限使用不扣背包、拒買免費品引導直接使用；付費與品牌合作商品購買入包；**軟下架（`discontinued`）商品商店隱藏但玩家背包裡已買的仍可繼續餵食**。
- **防損 JSON 存檔與版本遷移：** 純邏輯結構驗證與 `v1 → v2` 遷移（位於 `packages/game-core/src/save/`），搭配零外部依賴的本機原子寫入套件 `packages/storage-json`（`save.tmp → 驗證 → save.bak → 替換` 及壞檔自動救援）。
- **商店與存檔驗收看板（`apps/local-sandbox` Tab 3）：** 模擬商店頁、成分停留 3 秒倒數領分、買罐頭進背包餵食、以及手動存檔／重整網頁／模擬損毀救援按鈕。

### Out-of-Scope（明確排除）
- 不實作遠端 CDN 下載商品與廠商 API 連線（屬 Phase D）。
- 不實作手機端 SQLite 驅動（屬 Phase C，銜接設計見 [ADR-003](../../decisions/ADR-003-save-storage-json-to-sqlite.md)）。

## 3. 對應 Master PRD 哪幾點？

- **[Master PRD v2.1.30](../../PRD/AI_虛擬桌寵專案規格與需求書%20%28Master%20PRD%29.md) §2.1 無反感原生廣告五大原則：** 免費照護保障、品牌合作清楚標示、商品公平不賣數值。
- **§4.4 照護與商店探索系統：** 免費乾糧／飲水無限使用與背包自主選擇使用時機。
- **§8.C.2 商品目錄與軟下架狀態：** `active` / `pending_review` / `discontinued` 規則與 8 款預設商品效果。
- **§8.C.3 日常積分與商品探索任務平衡表：** 全部積分上限、20h＋本地日期防重與高健康日結規則。
- **§8.E.1 雙階段存檔與遷移規範：** `lastSimulatedAt` 單一權威時間戳、`save.tmp`/`save.bak` 防損流程與 `v1 → v2` 零外觀重置遷移。
- **§8.E.2 / §8.E.3 自動化驗收劇本：** `TC-07`、`TC-MH-11`。
