# SPEC-04｜30 日人格記憶、行為仲裁、CLI 與長時模擬

## 1. 這個 SPEC 的目的是什麼？

作為 Phase A 的**總組裝與終極壓力測試壓軸包**，負責把前面分開打造好的基因、時間、健康、商店全部組合成「一隻真正有性格、會生氣撒嬌、而且能穩穩養一年的活生生貓咪」：
1. **養出專屬靈魂：** 根據過去 30 天的摸頭、玩耍與餵食習慣動態演化四維人格（親人、慵懶、傲嬌、好奇），並在互動中自然觸發與揭露隱藏小怪癖。
2. **動作不打架：** 透過 6 級優先仲裁引擎決定貓咪當下該睡覺、討飯、撒嬌還是背對生氣，輸出乾淨的唯讀 `PetViewModel` 給所有平台直接播放。
3. **用 60 天／365 天真實跑完證明系統牢不可破：** 確認玩家每天只登入一次用免費糧水也能把貓養得健健康康、跑一整年零 `NaN` 不當機，作為進入 Phase B 手機端開發的正式封版門檻。

---

## 2. 要完成哪些功能？

### In-Scope（本 SPEC 涵蓋）
- **30 日滾動人格記憶與 4 款小怪癖修飾：** 最近 7 天佔 70%、第 8～30 天佔 30%（無歷史精確回歸品種基準）；4 款 MVP 怪癖採「先加後乘再限制 `[0.05, 0.95]`」，觸發時首次解鎖揭露至 `discoveredQuirks`。
- **6 級優先行為仲裁引擎（`BehaviorEngine`）：**
  - Priority `100`（緊急求救）> `90`（連戳 4 下或高空掉落生氣 4 秒 ＋ 15 秒互動冷卻，冷卻中餵食補水仍有效）> `80`（深夜 `23:00~07:00` 睡眠）> `60`（一般提醒 ＋ 60 秒冷卻）> `40`（主動互動 3 秒，傲嬌 `>= 70` 餵免費乾糧 45% 先撇頭再吃）> `10`（性格待機巡邏）。
  - 輸出跨平台唯讀契約 `PetViewModel`（嚴格剔除內部仲裁欄位 `interruptible` 與 `cooldownMs`）。
- **`GameEngine` 總組裝與雙介面同源驅動：** 以單一同步 `dispatch(command)` 串起全部子引擎，並打造 Windows 終端機互動養貓程式 `apps/local-cli`（支援互動與腳本自動化測試）。
- **60 日／365 日長時模擬驗收與 Phase A 結案報告：** 完整執行 `TC-08`（365 天隨機玩家穩定性）與 `TC-09`（60 日照護負擔全 5 子情境逐段零誤差對帳），並在看板繪製四大數值趨勢曲線圖。

### Out-of-Scope（明確排除）
- 不實作手機端 Rive 動畫播放、Android 懸浮窗、iOS Widget（屬 Phase B）或 LLM 自由對話（屬 Phase E）。

## 3. 對應 Master PRD 哪幾點？

- **[Master PRD v2.1.30](../../PRD/AI_虛擬桌寵專案規格與需求書%20%28Master%20PRD%29.md) §3.2 三層行為決策模型：** 基礎人格 30 日公式、小怪癖修飾順序與即時狀態調節。
- **§4.3 / §5.2 肢體語言與 `PetViewModel` 契約：** 無文字氣泡、8 種尾巴情緒、唯一 15 支 `AnimationId` 與平台唯讀投影規則。
- **§8.B.1～§8.B.3 行為仲裁與冷卻規則：** 6 級優先序、同級仲裁、POKE 10s 滑窗、15s／60s 獨立冷卻與傲嬌 45% 撇頭公式。
- **§8.E.2 自動化驗收劇本：** `TC-05`、`TC-06`、`TC-08`、`TC-09`（情境 A / B-1 / B-2 / B-3 / C 逐段參考時間表）。
